## 1. 本地目录

| 项 | 定稿 |
|---|---|
| 载体 | `export.localDir`（默认 `static/export`，配置见 §4） |
| 粒度 | **每任务一个子目录 `{app}_{md5}`** |
| 目录内容 | 固定名成员（中性名，如 `data.xlsx` + `attachments/…`），与"`name` 移出 zip"（08 §3.1）对齐；下载文件名仍取请求行 `name` |

- **命名理由**：`md5` = 产出规格摘要 ⇒ 同一目录 = 同规格重跑，覆盖安全（重试/复活回到同一目录，天然幂等）；`app` 段必须——task 身份是 `(app, md5)`，**跨 app 同 `md5` 若只用 md5 命名会目录撞名**。
- **单位口径**：程序内容量一律字节（与 `object.size` 同规）；给人填的配置用 MB（与 `max_size` 同规）。

## 2. 本地清理：双通道

| 通道 | 触发 | 动作 | 遗漏谁兜 |
|---|---|---|---|
| **① 同步**（worker 路径） | 上传成功 / `MarkFailed` / Abort 之后 | `os.RemoveAll` 本任务目录；幂等，目录不在即忽略 | — |
| **② mtime 扫描**（后台，第 8 条任务线） | 周期性扫 `localDir`，`mtime < now - localTtl` 即删 | — | 崩在"上传成功但删本地前"、进程被 kill 的残留 |

- `localTtl` 建议 **≥ 3 × `export.lease`**：阈值必须大于"单次最长导出 + 一轮重试"的时间，否则会把在产的目录误删（生产中目录持续被写，`mtime` 自然刷新，不会踩到）。
- **启动时也扫一次**：进程重启即清——未完成任务本来就整份重跑（导出是无状态纯函数，08 §9），不存在"清掉半成品可惜"的问题。
- **多实例安全**：各实例只扫本机盘；谓词是本地事实（mtime），无协调、幂等、谓词自带排他。
- **显式接受**：通道②阈值之内的残留最多浪费 `localTtl` 时长的磁盘。

## 3. 容量感知调度（两层结构）

### 3.1 分层与职责边界

| 层 | 组成 | 管什么 | 承担 |
|---|---|---|---|
| **分发层** | 节点注册表 + 分发线程 + owner 指派 | 该谁做 | **成本**（坏了只是分得不好） |
| **生产层** | `Claim` CAS + `leased_at` 租约 + 租约恢复任务 | 谁在做 | **正确性**（防双产） |

- 关系与"重建锁 vs 读路径"同构：owner 只是调度偏好，**Claim CAS 才是生产权**。
- **删除"创建时亲和锁"**（08 §7.1 旧案整节重写）：被 owner 指派取代。全服务分布式锁仍是两把（缓存重建 + owner 分发），不增加。

### 3.2 节点注册表（数据结构）

```
ZADD  resource:export_nodes <expire_ts> <uuid>     # score = 心跳过期时间戳
HSET  resource:export_nodes <uuid> <free_bytes>    # 同一 hash 存容量
```

- **心跳**（复用 `export.heartbeat`，一个 Lua 写两处）：`expire_ts = now + nodeTtl`；`free_bytes` = 心跳时探测的 `localDir` 所在卷剩余空间。
- **清理**（第 9 条任务线，任何实例可跑、幂等）：`ZREMRANGEBYSCORE resource:export_nodes -inf now` + Lua 同步 `HDEL` 对应字段。
- **机器下线无需任何额外机制**：心跳停 ⇒ TTL 到期 ⇒ 自动离表。这正是旧亲和锁缺的（它只处理"创建机挂"，不处理"任意节点挂"）。
- 不用 zset 的 member 编时间戳——那种形态清理线程无法高效删过期项，只能全扫。

### 3.3 下发与认领（时序）

```
分发线程（每实例都有，无单点）：
  ListClaimable 取候选（status=0，或 status=3 且退避到期；ORDER BY failed_at, id 不变）
    → 读注册表：未过期 ∧ free ≥ reserve + estimate（§3.4）→ 按容量降序取第一个节点
    → SET resource:export_task:{id}:owner <uuid> NX PX lease     # 原子指派；NX 失败 ⇒ 换下一个任务
    → SADD resource:export_node:{uuid}:tasks <id>（EXPIRE 同 lease）
        ↓
节点本地消费循环（worker 池旁）：
  SMEMBERS resource:export_node:{my_uuid}:tasks
    → 本地容量复检：不足 ⇒ Lua 比对 token 后 DEL owner + SREM（主动归还，等有余量的节点）
    → Claim CAS（status IN (0,3) ∧ retry<3 ∧ 退避到期 ⇒ 1, retry+1, leased_at=now）
    → RowsAffected==0 ⇒ SREM 跳过（已被别人领走 / owner 过期被重分，CAS 仲裁）
    → 生产：心跳顶 leased_at 的同一个动作里续 owner TTL（SET PX lease）
    → MarkSuccess / MarkFailed ⇒ SREM 出队
```

- **排队中的任务不续 owner**：本地队列里等 worker 槽位的任务，owner 到期自然释放、可被重新指派；两个节点同时 Claim 由 CAS 仲裁（一个 `RowsAffected==1`）。**排队等余量不是失败。**
- **owner TTL = `export.lease`**（复用，不新造配置项）：它要覆盖的窗口与"单次导出最长耗时"本来就是同一个量。
- **删掉"重试一直被这台机器调度"**：硬绑定需要把 owner 持久化（新列）或禁止重分（损害健康性），收益只是省一次重跑，而导出是纯函数、重跑写同一个键、字节相同。**建议显式接受"重试可能换节点"**，不建绑定。

### 3.4 容量准入（软约束）

```
estimateSize(spec) = rows × ROW_BYTES_EST（代码常量，含放大系数）
                   + Σ files 对应 object.size（批量查，不透传前端声明）
准入式：free_bytes ≥ reserve + estimateSize(spec)
```

- **事前大小不可知是这条的全部难点**：`export_task.size` 是 `MarkSuccess` 时才有的；rows 是服务端生成的（估），files 的 `object.size` 是硬事实（批量查，不是 N 次 `HeadObject`）。
- **它是软闸，不是硬保证**：低估 ⇒ 生产中磁盘满 ⇒ 写失败 ⇒ `MarkFailed` ⇒ 退避重试（届时可被有余量的节点接手）。文档必须写明"准入只降低概率，兜底是失败重试"，否则运维会把它当容量承诺。
- 估不准的极端（rows 巨大 / files 上万）⇒ 按上限估，**宁可排队**。

### 3.5 无节点可调度

- 本轮注册表里没有满足 `free ≥ reserve + est` 的节点 ⇒ **不动任务状态**（保持 `status=0` 或退避中），下一轮再试。
- **绝不标记失败**：终态失败只属于 `retry >= maxRetry`（08 §6）——"集群暂时忙"不是任务失败，把临时无资源变成永久失败会让用户白白点一次手动重试。

## 4. 配置（11-配置 `business.export` 新增）

| 键 | 建议值 | 说明 |
|---|---|---|
| `reserveMb` | 5120 | 单节点准入的预留磁盘（MB；人工录入用 MB，同 `max_size` 约定） |
| `nodeTtl` | = `heartbeat` | 注册表心跳 TTL |
| `localTtl` | ≥ 3 × `lease` | 本地残留 mtime 清理阈值 |
| 复用 | `lease` / `heartbeat` / `workerCount` | owner TTL / 注册表心跳 / 节点生产并发 |

## 5. 失效模式（判据：这个机制坏了会怎样）

| 机制 | 承担 | 坏了 | 后果 |
|---|---|---|---|
| 注册表心跳 | 成本 | 误删活跃节点 / 误留死节点 | 少一个分发目标 / 卡到 owner 到期后重分；**正确性无损** |
| owner SETNX | 成本 | 过期重分导致双 Claim | `Claim` CAS 仲裁；同键同字节覆盖无害 |
| 容量准入 | 成本 | 低估 | 生产中磁盘满 ⇒ `MarkFailed` ⇒ 重试 / 换节点 |
| mtime 清理 | 成本 | 误删进行中？**不会**（阈值 > 单次最长生产时长，写盘即刷 mtime）；误留 | 浪费磁盘，下轮再清 |
| 分发线程 | 成本 | 挂了 | 其他实例的分发线程照跑；**无单点** |
